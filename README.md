# 歌舞賭(KABUTO)

iPhone専用の麻雀スコア・精算記録アプリの初期実装です。SwiftUI / iOS 17以降。外部サービス、アカウント、サーバーは使いません。

## 使い方

1. 「ルール」で開始点・返し点・ウマ・金額換算の単価を設定します。初期値はMリーグの点数ルールで、金額換算はオフです。
2. 「点数入力」の「名前を登録・変更」で4人の名前を登録します。「順位順」で1位〜4位の名前を選び、それぞれの最終持ち点を入力します。従来の「名前順」にも切り替えられます。供託は受け取り先の持ち点に加算してください。
3. 「結果を確認する」でスコアの内訳と各人の支払額・受取額を確認し、「この結果を保存」を押します。
4. 「記録」で半荘ごとの結果と累計収支を確認します。記録を左にスワイプすると、確認後に削除できます。

入力途中の値・ルール・記録は端末内のApplication Support/Soshima/records.jsonに保存します。保存失敗は画面に表示し、読み込み不能時は元のファイルを上書きしません。アプリ削除時にデータは失われます。

## 計算ルール

- 丸め前のスコア =（最終持ち点 − 返し点）÷ 1,000 + ウマ + オカ + 飛びボーナス。端数処理を有効にすると、この合計に選択した丸めとトップ調整を適用します。
- オカ合計 =（返し点 − 開始点）× 4。1位へ加算します。
- Mリーグ設定：25,000点持ち、30,000点返し、ウマ +30 / +10 / −10 / −30、オカ20,000点。
- 例：42,000 / 31,000 / 18,000 / 9,000点 → +62.0 / +11.0 / −22.0 / −51.0。
- 同点は該当順位のウマを均等配分。1位同点はオカも均等配分します。座順優先にはしません。
- 内部計算は1/60スコア単位の整数で行い、3人同点でも合計0を保持します。表示は小数1桁なので、同点時は表示値の合計に丸め差が出ることがあります。
- 円換算は丸め前のスコアに設定単価を掛け、最大剰余法で1円単位に調整します。同じ端数なら結果の表示順を優先します。受け取りと支払いの合計は一致します。
- 金額換算と精算額の表示はアプリ独自機能です。Mリーグの金銭精算ルールを意味しません。
- 持ち点は100点単位。合計不一致、名前重複、ウマ合計が0以外の記録は保存しません。

## Macで起動

Xcode 16以降で `Soshima.xcodeproj` を開き、`Soshima` スキームとiPhoneシミュレーターを選んで実行してください。実機に入れる場合はSigning & Capabilitiesで自身のTeamを選択します。Bundle IDの変更が必要なら各自のIDに変更してください。

```sh
cd /path/to/soshimahjong
xcodebuild -project Soshima.xcodeproj -scheme Soshima \
  -sdk iphonesimulator -configuration Debug \
  -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build
```

## 計算テスト

Swift 5.9以降で実行できます。XcodeなしのLinuxでも計算部分を検証できます。

```sh
cd /path/to/soshimahjong
swift test
```

このクラウドではSwift 6.0.3で計算・順位入力・端数処理テスト31件を実行しました。iOSのSDKがないため、SwiftUI画面の型チェック・iOSビルド・シミュレーター操作は未検証です。構文解析だけでiOSビルド成功とは扱っていません。

## 初期版の範囲とリリース前の作業

現状は同じ4人での記録用です。名前を編集しても各入力枠の参加者IDは維持されます。別メンバーの対局管理、期間別集計、記録の編集、入出金済み管理、データ書き出し・復元は未実装です。記録を訂正する場合は削除して入力し直してください。

App Storeへの公開はしていません。Macでのビルドと実機確認、アプリアイコン、署名、ストア情報とプライバシー情報の準備が必要です。大きい文字サイズ、ダークモード、VoiceOver、キーボード操作、保存後の再起動、履歴削除を実機でも確認してください。

クラウド作業は既存のチェックアウトをそのまま使用します。ユーザーの明示的な依頼がなければGit worktreeは作成しません。

## レビュー反映（入力と飛び終了）

- 赤を基調とし、持ち点・スコア・精算額・設定値の数字を拡大しています。結果の素点・ウマ・オカは項目ごとに分け、大きな数字で表示します。
- 名前欄と点数欄の両方をフォーカス管理し、キーボード上の「完了」で閉じます。「次へ」で名前から点数、次の点数へ移動できます。
- 「1スコアあたりの円」は、換算なし / 30 / 50 / 100 / 200 / 500 / 1000 / その他のメニューから選びます。「その他」は直接入力です。
- 「ルール」で飛び終了をオンにすると、最終持ち点が0点未満の対局を飛び終了として保存します。0点ちょうどは対象外です。対局中の自動検知機能はありません。
- 飛びボーナスは0〜1000スコアで設定し、初期値は10です。飛んだ人から飛ばした人へ移します。0ならボーナスなしです。
- 飛んだ人がいる場合は、点数入力画面で飛ばした人を選択します。複数人が飛んだ場合は、それぞれ選択が必要です。飛んだ本人と他の飛んだ人は受取先にできません。
- Mリーグのプリセットは飛び終了なしです。プリセット選択後に飛び終了をオンにするとカスタムルールとして使えます。
- 古い保存データは飛び終了オフとして読み込み、過去のスコアを変えません。

Macで最新版のファイルに更新し、元と同じBundle IDとTeamで実行してください。既存記録を保持するため、iPhoneからアプリを削除する必要はありません。入力の使いやすさとキーボードの動作は実機確認が必要です。

数字の表示は共通のNumberFontで従来サイズの1.2倍に統一しています（持ち点34→40.8pt、結果スコア34→40.8pt、ルール入力22→26.4pt）。Dynamic Typeによる拡大も維持し、計算値・保存値は変更しません。

## 順位順で入力

- 点数入力の初期表示は「順位順」です。1位〜4位ごとに、登録した4人の名前をメニューから選び、その下に持ち点を入力します。
- すでに他の順位で選んでいる名前を選ぶと、2人の名前が入れ替わります。入力済みの点数は各順位の欄に残し、新しく選んだ名前に紐づけ直します。
- 「名前を登録・変更」で名前を編集できます。保存時に空欄や名前の重複を確認し、キャンセルした変更は反映しません。
- 順位順では持ち点が上から多い順か確認します。逆転していれば該当順位の確認メッセージが出ます。同点は入力でき、結果では同順位・ウマとオカの均等配分として計算します。
- 「次へ」は表示順の1位→2位→3位→4位で進みます。名前順へ切り替えると、選択済みの各人の点数を維持します。順位順へ切り替える際は、現在の持ち点が多い順に並べます。
- 入力方法・選択した名前の順位・入力途中の点数は端末内に保存します。以前の保存データも読み込み可能です。既存の記録、参加者ID、集計方法は引き継ぎます。

## 精算の表示

結果画面の精算は、各人の収支をまとめて表示します。例えば負けた人は「2,200円の負け」「全体に支払う合計 2,200円」、勝った人は「受け取る合計 6,200円」と表示します。収支が0円なら「支払い・受け取りなし」です。支払い相手の割り振りは表示しません。

記録画面の「これまでの合計」も同じ形式で表示します。保存済みの全半荘の収支に基づく累計額で、実際に支払ったかどうかは管理しません。

## スコア端数の処理

「ルール」→「スコア端数の処理」で「1スコア単位に丸める」をオンにすると、次の4種類から選べます。

| 方法 | 正の例 | 負の例 |
| --- | --- | --- |
| 切り上げ | +12.4 → +13 | −12.4 → −12 |
| 四捨五入 | +12.5 → +13 | −12.5 → −13 |
| 五捨六入 | +12.5 → +12、+12.6 → +13 | −12.5 → −12、−12.6 → −13 |
| 切り捨て | +12.4 → +12 | −12.4 → −13 |

切り上げは数直線のプラス方向、切り捨てはマイナス方向です。四捨五入・五捨六入は絶対値の小数部分を基準に処理してから符号を戻します。五捨六入の境界は0.6です（12.5833… → 12、12.6 → 13）。

素点・ウマ・オカ・飛びボーナスを合計したスコアを丸めます。4人のスコアの合計が0になるよう、丸め後の差分は1位の「トップ調整」に加えます。このため1位の最終スコアは、単独で丸めた値と異なる場合があります。同点1位のトップ調整は均等に分けるため、最終スコアに小数が残る場合があります。入力順で同点者の有利不利を付けません。

結果画面には「端数処理」と「トップ調整」の内訳を表示し、調整後のスコアで金額を換算します。例えば四捨五入で同点1位の調整が必要な場合、35.6 / 35.6 / −24.9 / −46.3 は 35.5 / 35.5 / −25 / −46 になります。

この機能は初期状態ではオフで、Mリーグのプリセットでは小数を保持します。設定は各記録に保存するため、現在のルールを変更しても保存済みの結果は変わりません。旧バージョンのデータは端数処理なしとして読み込みます。
